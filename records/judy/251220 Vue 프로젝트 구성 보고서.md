# 251220 Vue 프로젝트 구성 보고서

## 1. 프로젝트 개요
본 프로젝트는 Vue 3 + Vue Router 기반의 SPA(Single Page Application)로,
페이지(View)와 UI 컴포넌트(Component)를 명확히 분리하여 유지보수성과 확장성을 고려해 구성하였다.

주요 목표는 다음과 같다.
- URL 단위의 화면(View) 분리
- 재사용 가능한 UI 컴포넌트 설계
- 데이터 흐름을 상위 → 하위로 명확히 관리

---

## 2. 전체 구조 개요

```text
src/
 ├─ assets/
 │   └─ main.css
 │
 ├─ components/
 │   ├─ Header.vue
 │   ├─ SearchBar.vue
 │   ├─ ProductCard.vue
 │   └─ LoginModal.vue
 │
 ├─ views/
 │   ├─ HomeView.vue
 │   ├─ CommunityView.vue
 │   ├─ LoginView.vue
 │   └─ ProfileView.vue
 │
 ├─ router/
 │   └─ index.js
 │
 ├─ App.vue
 └─ main.js
```

---

## 3. App.vue 역할

App.vue는 애플리케이션의 최상위 레이아웃 역할을 수행한다.
한 번 렌더링되면 사라지지 않으며, 공통 UI와 페이지 영역을 포함한다.

```vue
<template>
  <Header />
  <RouterView />
</template>
```

- `Header` : 모든 페이지에서 공통으로 사용
- `RouterView` : URL에 따라 View를 교체하는 영역

---

## 4. Router 구조

Vue Router를 사용하여 URL과 View를 1:1로 매핑하였다.

```js
{
  path: '/',
  component: HomeView
}

{
  path: '/community',
  component: CommunityPage
}

{
  path: '/login',
  component: LoginView
}
```

RouterView는 현재 URL에 맞는 View 컴포넌트를 렌더링한다.

---

## 5. Views 설계 (페이지 단위)

### View의 역할
- URL을 대표하는 페이지
- 데이터의 주체 (상태 관리)
- 여러 컴포넌트를 조합하여 화면 구성

### 예시: CommunityPage.vue
- 상품 목록(items) 관리
- 선택된 상품(selected) 상태 관리
- 선택된 상품을 기준으로 상세 영역 출력

```js
const items = [...]
const selected = ref(items[0])
```

---

## 6. Components 설계 (UI 단위)

### Component의 역할
- 페이지 내부에서 사용되는 UI 부품
- props로 데이터 전달받아 화면 출력
- 이벤트 발생 시 emit으로 부모(View)에 알림


---

## 7. 데이터 흐름 설계

본 프로젝트의 데이터 흐름은 단방향 구조를 따른다.

```text
View (데이터 소유)
   ↓ props
Component (표현)
   ↑ emit
View (상태 변경)
```

- 데이터는 항상 View가 소유
- Component는 표현과 이벤트 역할만 담당

---

## 8. Login 화면 설계

Login은 일반 페이지 전환이 아닌 전역 모달 UX로 설계하였다.

- URL: `/login`
- 화면: `LoginModal.vue`
- 제어 위치: App.vue

```text
URL 변경 (/login)
   ↓
App.vue에서 감지
   ↓
LoginModal 표시
```

이를 통해 어떤 페이지에서도 동일한 로그인 UI를 제공한다.

---

## 9. 정리

- View와 Component의 책임을 명확히 분리
- 상태는 가장 상위 공통 부모(View)에서 관리
- UI는 재사용 가능한 Component로 구성
- URL 중심의 페이지 구조 유지

본 구조를 통해 유지보수성과 확장성을 고려한 Vue 애플리케이션을 구성하였다.
